Do not reset or overwrite work to force a patch. For a new checkout:

    git clone --branch audiobook-support https://github.com/HariOcto/rsoul.git rsoul-v11
    cd rsoul-v11
    git switch --detach 612a90e5e32f6250c9c7b77d8a6a84278e815e5b

Verify the exact base and a clean working tree:

    git rev-parse HEAD
    git status --short

Check and apply using the actual downloaded file path:

    git apply --check /path/to/rsoul-github-to-v11.patch
    git apply /path/to/rsoul-github-to-v11.patch

Alternatively, after the check, use git am on the same file to create one
commit. Do not apply twice. Do not force rejected hunks.

CHECK AND BUILD

In a Python 3.11 or 3.12 environment:

    python -m pip install -r requirements-dev.txt
    python -m pytest -q tests
    bash -n run.sh
    python rsoul.py --version

Expected: R:soul 11 (v11)

On a Docker-capable build host, from this patched source:

    docker build -t rsoul:v11 .

Make the built image available to the deployment host and configure the
TrueNAS app or Compose service to use it. The sample Compose file selects
an image without a build entry. Restarting an old container or pulling an
unrelated latest image does not install the changed source.

CUT OVER

Stop the old rsoul instance, back up its actual persistent data directory,
and retain downloads and sidecar journals. Preserve existing credentials,
URLs, UID/permissions and mounts. Start one instance with the new image
and the same persistent state. Do not clear state to force a clean start.

Inside the running new container:

    python /app/rsoul.py --version
    python -m rsoul.diagnostics --config-dir /data

For the mappings in the supplied logs, /downloads inside rsoul and
/downloads/slskd/downloads inside Chaptarr may correctly refer to the same
physical files. Retain that mapping when it is correct. Use targeted
import explicitly: RSOUL__READARR__IMPORT_METHOD=targeted.
